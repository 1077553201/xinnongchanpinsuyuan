# 前端第 1 阶段：联调基线与基础体验

日期：2026-10-20。实现依据：`PROJECT_GOAL.md`、`FRONTEND_PREPARATION.md`、现有前后端代码。旧准备文档中的「前端为 0」为历史状态，当前进度以本记录和实际代码为准。

## 已实现

- 沿用晨光玻璃设计，修复 `GlassPanel` 布尔联合类型导致默认内边距失效的问题。
- 增加 `ResourceState`、`useAsyncResource`，统一独立加载、空状态、错误和重试；刷新时清除旧结果，旧请求不能覆盖新结果。
- 总览支持整页刷新和单项重试。请求失败不显示零值；告警明确为最近最多 6 条，包含已处理记录。
- 链健康依据 `status` 判断连接；`chainEnabled` 独立说明写链配置是否齐备。页面称账户为「调用账户」。
- 公众页区分查询失败、未找到、待确认、禁用、未知和摘要不一致；标题、印章和记录状态采用相同判断。只有完整、确认且摘要一致的记录可显示「摘要记录一致」。
- 全局交易确认标签改为「上链已确认」。未知质检结果显示「结果待确认」，不推断为合格。
- 查询切换有请求顺序保护。后台查询入口改为输入真实溯源编号，不再固定跳转演示码。
- 增加共享按钮、字段、校验提示样式，供第 2 阶段表单复用；复杂表格随业务页实现。

## 第 2 阶段产品与批次契约

统一响应为 `{ code, message, data }`，成功 `code` 为字符串 `"0"`；沿用 `src/api/http.ts` 解包。当前 GET 列表没有服务端分页参数，页面只能对已取得的数据做本地筛选；后续数据增长时另补分页接口。

| 操作 | 接口 | 请求与响应约定 |
| --- | --- | --- |
| 产品列表/详情 | `GET /api/products`、`GET /api/products/{id}` | 返回实体数组/实体；不假设已支持编辑或删除 |
| 新建产品 | `POST /api/products` | 必填 `organizationId`、`productCode`、`productName`、`category`；可选 `variety`、`originPlace`、`description` |
| 批次列表/详情 | `GET /api/batches`、`GET /api/batches/{id}` | 使用 `productId` 关联产品；显示业务状态与 `chainStatus` |
| 新建批次 | `POST /api/batches` | 必填 `productId`、`organizationId`、`batchCode`；日期为 `yyyy-MM-dd`；可选 `productionArea`、`metadata` |
| 关闭/召回 | `POST /api/batches/{id}/close` | `status: 2` 关闭，`status: 3` 召回；`reasonPayload` 为对象；操作前二次确认 |

组织字段目前为数值 ID，不假设存在组织选择接口。UI 校验必填、去除首尾空白、正整数 ID 和日期先后；后端当前注解只检查部分必填项，业务规则不能仅依赖前端。业务保存成功与上链成功分别反馈，`CHAIN_DISABLED`/`FAILED` 不伪装成已确认。后端确认结果不明时先重新查询，不能盲目重发创建或写链操作。

## 保留的边界

本阶段未补实时链上摘要核验、按批次筛选公众环境数据、交易列表接口、NFC 查询接口、登录鉴权或 AI 服务。这些分别随后续业务阶段处理。当前环境摘要仍是后端返回的全局近期窗口，页面已明确标记「批次归属尚未核实」，不能作为当前产品环境归属已验证的证据；公众页完整验收须补此关联。
