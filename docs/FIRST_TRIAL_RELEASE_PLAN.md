## 1. 首版交付定义

围绕一套试点资料，让固定传感器和检测车分别产生实际硬件采样，经网关、MQTT、后端和数据库形成可追溯的记录与窗口，最终在 FISCO 中核对真实摘要，并从管理端及公众页查回来源。

台架实机联调可以作为技术试用，必须标注“台架”；业务演练必须标注演练，不能冒充真实采收、发货或签收。现场经营验收只记录实际发生的事实，不用一天软件数据冒充完整生长季。首版不等于完整 ERP、全自动车控或生产级长期运维认证。

```text
固定传感器 → 固定网关 ─┐
                     ├→ EMQX → 后端校验与归属 → MySQL 原始记录/窗口
检测车传感器 → 车载网关┘                         ↓
                   地块/周期 ← 绑定历史或独立巡检任务
                                                ↓
                   规范化摘要 → FISCO 交易/回执 → 实时读链核验
                                                ↓
                   管理前端 → 包装来源/二维码或 NFC → 公众查询
```

Broker 可连接、数据库有行、链交易成功、页面能打开，各自只证明一个检查点；必须用同一组样本关联起来。

## 2. 推进顺序

| 批次 | 本批范围 | 结束标准 |
| --- | --- | --- |
| T0 范围与环境 | 试点、设备/固件档案、地址、运行方式、已知问题复现 | 有设备表、真实报文和可执行环境，不再按菜单补功能 |
| T1 固定采样贯通 | 真实传感器→网关→EMQX→后端→数据库→监测页；修设备反馈 | 同样本全来源可查，绑定历史正确，断线和错误可解释 |
| T2 检测车闭环 | 独立任务、地块/区间、真实采样、结果与回执归属 | 一次实际车载采样任务可追溯，不再冒充固定绑定 |
| T3 证据与实物查询 | 同样本→窗口/生产证据→链回执→前端核验→手机扫码 | 来源、摘要、交易与码对应，失败和缺失如实显示 |
| T4 收尾交付 | 业务回归、设备缺陷、手机页面、新机部署、备份恢复和说明 | 目标环境可复现试用，阻塞项清零，交付版本留档 |

检测车按已有硬件能力确定最小闭环。允许明确标注的人工驾驶和人工指定任务地块，这不等于自动导航或远控。支持命令/ACK 时验证真实下发与回执；不支持时不得用日志或页面状态伪造成功。没有可靠地块/时间依据的车载样本保持待核实。

## 4. 首版阻塞项清单

### 环境与固定设备

- [ ] TR-01 冻结试点配置和设备清单，隔离 QA、台架与经营数据；既有 QA 链记录保留标记，不删除掩盖。
- [ ] TR-02 目标部署形态下前后端、MySQL、FISCO、EMQX 重启可用；核对地址、端口、数据库 Host 权限和 MQTT 实际启用状态。
- [ ] TR-03 复现并处理 DEVICE-001/002，回归登记、绑定、解绑、换地、刷新、筛选和历史归属。
- [ ] TR-04 至少一套真实固定传感器上报，值、单位、采集时间和归属一致，覆盖至少一个完整配置窗口。
- [ ] TR-05 核对 Broker 认证/Topic 权限与采样端身份，实现试点必要的验签或其他可信身份机制；保存 signature 不等于验签。
- [ ] TR-06 明确并验证重复、乱序、延迟、设备重启、缺失时间、重连与补传规则，重复消息不重复充当独立采样。

### 检测车与来源

- [ ] TR-07 确认真实车载固件和报文，保存实际输出样本及台架/现场测试方式。
- [ ] TR-08 补齐最小巡检任务身份、地块/时间区间和状态回执，车载样本可关联任务，跨地数据不沿用固定绑定。
- [ ] TR-09 实际跑通一次任务采集→上报→入库→查询；有命令通道才验证真实 ACK，人工动作明确标注。

### 链上证据与业务查询

- [ ] TR-10 明确新周期环境存证时点。现有无批次窗口仍为 CHAIN_DISABLED；要求生长期持续逐窗上链时，须补齐对应新来源路径。
- [ ] TR-11 同一组硬件采样形成来源清楚的窗口/生产证据，保存摘要与交易哈希，并从 FISCO 读回核对。
- [ ] TR-12 回归来源→农事/采收包装→库存→订单→运输→逐件结果的主线。演练明确标注，真实动作只在实际发生后录入。
- [ ] TR-13 实物贴码后手机查询回到同一来源；采用 NFC 则实际写入碰触验证。缺真实质检报告不显示合格。
- [ ] TR-14 停链、停库、断 Broker、错误设备、来源不明和未存证如实展示，恢复核对不盲目重发链操作。

### 可试用交付

- [ ] TR-15 回归加载、空状态、错误重试、确认、主题、全宽布局及手机右侧导航，消除阻塞问题并补视觉验收。
- [ ] TR-16 验收已有助手常见查询和开放操作的确认/轨迹/错误提示，明确尚不支持的操作，不宣称全业务可对话执行。
- [ ] TR-17 干净数据库与目标电脑验证初始化、全部增量迁移、启动和配置；示例数据不自动混入经营数据。
- [ ] TR-18 在独立环境演练数据库与必要私密配置的备份恢复，保持链引用一致，密钥/证书不提交仓库。
- [ ] TR-19 留存版本、依赖清单、前后端交付物、配置模板、部署/操作说明、已知限制及问题清单。
- [ ] TR-20 汇总同一试点的全链路证据，阻塞项清零后给出可试用、受限可试用或不通过的结论，不只依据测试数量。

## 5. 最小证据与异常用例

每条证据记录：环境/固件版本、时间、设备/网关、地块周期或任务、采样标识、数据库记录、窗口摘要、业务来源、交易/回执、读链结果与页面入口。不记录密码、设备密钥或私钥。

| 用例 | 必须观察的结果 |
| --- | --- |
| 固定设备正常采样 | 实际值、单位、时间和归属一致，模拟数据不混入 |
| 检测车跨地/任务结束 | 区间明确，结束后样本不误属上一块地 |
| 换地与迟到样本 | 按历史采集时点判定来源，不用当前绑定覆盖历史 |
| MQ 初次失败/中途掉线 | 状态可见、可恢复，补传与去重可解释 |
| 链关闭/失败/未知回执 | 如实显示，核对恢复不制造重复事实 |
| 新电脑与手机访问 | 配置可复现、扫码地址可达，0.0.0.0 仅作监听地址 |
