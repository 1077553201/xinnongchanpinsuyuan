## 本轮可用范围

输入一段日报并选择具体日期，系统保留原文，拆成事项；每项显示原文引用、办理类型、来源和缺项。首版执行工具仅开放**实际采收登记、运输事实登记**，复用 `HarvestService`、`TransportService`；不直接改业务表、不下发设备指令、不新增上链事实。

包装、入库、销售、农事和设备控制等暂作待办；已发生、计划、否定和不明确事项需分别核对。尚未提供多轮对话追问、附件理解、依赖事项自动编排和全局悬浮对话入口，不将首版表单确认流程视为完整自然对话 Agent 已完成。

## 使用步骤

1. **整理：** 填写日报日期和原文，一次最多 12,000 字、20 项。整理草稿不产生采收、库存或运输变动。
2. **核对：** 查看逐项原文，搜索当前权限内的种植周期或运输单（每类最多 50 项）；补齐具体发生时间、人员、单位、数量等。不会用当前时间、登录人员或剩余重量代替未知现场事实。
3. **保存新版本：** 修改后先保存，服务端重新核对字段和来源状态。原文与事项标识保留，每篇最多 100 个版本。成功事项锁定，不能改写后再次执行。
4. **选择确认：** 只勾选已补齐、未成功的事项。确认框显示版本、实际字段及影响；计划和其他事项可以保持待办。确认不代表链上存证或设备完成。
5. **查看回执：** 每项独立保存，成功项保留，失败项显示原因；补齐失败项后保存新版本，只重试需要处理的事项。收货结果沿用运输服务的数量、时间和状态校验，不自动退库或退款。

同一来源中有前后依赖的事项分轮办理。例如“发运 → 收货”在发运后来源已变化，旧收货草稿需重新保存、核对和确认，不在首版中自动推导依赖、数量或新业务编号。

## 模型配置与真实状态

本机 `.env` 当前未配置模型，因此页面明确显示“本地规则整理”。此模式只尝试识别部分中文采收表达和阿拉伯数字重量，如“今天采收80斤”；“八十斤”、具体时间、人员、业务匹配等需人工补充。计划、否定和其他表达保留待办。规则不是大模型理解，也不是硬件或现场证据。

需要模型整理时，在本地 `.env` 配置并重启后端：

```dotenv
AI_PROVIDER=compatible
AI_BASE_URL=https://<你的模型服务地址>/v1
AI_MODEL=<服务支持的模型名称>
AI_API_KEY=<仅在本地填写密钥>
```

适配服务须支持基础地址下的 `POST /chat/completions`、Bearer 认证、JSON 对象响应格式及 `choices[0].message.content`。本机模型可用回环 HTTP，外部服务使用 HTTPS。服务不可用或返回无效内容时明确报错，不静默伪装成模型成功或切换规则模式；显式设置 `AI_PROVIDER=disabled` 才使用规则模式。

模型收到本次日报、日期、时区和当前权限内最多 50 个周期/运输候选标签；不发送数据库凭据、模型密钥、完整客户地址或原始传感器历史。模型只能提出受限事项，工具名、引用、字段和来源由后端重新检查。完全相同的模型建议去重；用户文本和检索标签不能提升权限或跳过确认。

## 持久化与可靠性

- 个人日报仅限提出人查询和办理，管理员也不能通过此入口代看其他人的原文；实际业务仍受当前机构和角色限制。只读人员不能创建、修改或执行。
- `agent_report` 保存原文、日期与提出人；`agent_revision` 保留历史操作版本；`agent_confirmation` 绑定确认人、版本和操作范围；`agent_receipt` 保留逐项结果与业务编号。
- 同一提出人、相同日期与完全相同的去首尾空白原文返回既有日报。仅为精确重复识别，不保证语义相似日报、改写原文或跨日报的重复事实可自动识别。
- 执行前锁定日报和业务来源，重新核对权限、版本与来源状态。业务写入、成功回执和审计同事务保存；失败事务回滚后单独记录失败回执。成功项的判断查询完整历史，不依赖页面“最近 200 条”显示范围。
- 每项使用服务端稳定确认键；重复确认复用原范围与回执。有未结束确认时禁止修改或另起一轮，刷新后可“恢复原确认并核对结果”。恢复不等于整单重做，已落账事项不重复执行。
