# 环境规则与农事作业阶段记录

更新时间：2026-10-21。本阶段延续 [生产到销售及 Agent 规划](PRODUCTION_TO_SALES_AGENT_PLAN.md) 的生产基础建设；设备管理和绑定数据反馈记入 [待优化清单](OPTIMIZATION_BACKLOG.md)，尚未作为已修复事项。

## 页面与操作

登录后进入“环境与农事”（`/admin/farming`），选择具体种植周期；地块与种植详情也提供入口。沿用晨光绿、柔光玻璃主题。

- **农事作业：** 安排灌溉、施肥、植保、修剪、除草、巡检或其他任务，指定负责人和计划日期。实际作业后另行登记执行时间、投入品、用量、说明和凭证引用；施肥及植保必须填写投入品、用量与单位。计划不会自动成为完成记录，取消必须填写原因。
- **环境要求：** 按周期配置温度、湿度、土壤湿度或光照范围，填写实际依据及预期采集间隔。至少填写一个边界，不提供农艺默认值；确认时生效，替换或停止规则均保留旧版本。
- **异常处置：** 对超范围样本登记已采取措施和观察结果，保留操作人员、时间及原始超范围判断。“已记录处置”不表示环境已恢复。

## 数据与业务边界

仅来源为 `RAW` 且已明确绑定种植周期的正式样本进入新规则判断。按采集时间匹配当时有效的规则版本，迟到样本仍使用旧范围；无规则、单位不匹配分别记录，不能据此显示合格。兼容摄氏度、百分比、照度的单位别名，不自动换算华氏度。上线前旧样本不自动补算，模拟上报不产生正式判断或异常。

采集及时性提示与范围判断分别展示；一条样本在范围内不能证明整轮种植或产品质量合格。新异常档案与原有全局 IoT 告警分别保留，未将旧设备数据问题视为已解决。

机构范围及写权限由后端统一检查。任务负责人或管理员可登记完成；管理员代录同时保存实际执行人与录入人。执行记录单独保存，重复或并发提交同一确认不会重复完成；环境规则保存也校验确认键及内容。当前没有执行记录更正或图片上传流程，凭证引用仅为文本。

存在待执行农事或未记录处置的环境异常时，不能结束种植；结束日期不得早于实际农事日期。成功结束时停止沿用本轮规则，历史记录仍可查询。

列表当前上限：任务 200 条、规则 200 个版本、样本判断与异常各 100 条；待执行任务、当前规则和待处置异常优先展示，不代表完整导出。

## 数据库升级

新环境的 `database/schema.sql` 已包含五张新表。已有环境先完成前两批迁移，再执行 `database/migrations/003_growing_operations.sql`；不要重新初始化或加载示例数据。该迁移仅新增规则、判断、异常、任务及执行表，不改写旧记录。

也可从仓库根目录使用本机 Java 11 和已有 JDBC 驱动，连接配置从本地 `.env` 读取：

```powershell
& '<Java 11目录>/bin/java.exe' '-Dfile.encoding=UTF-8' -cp '<mysql-connector-java.jar路径>' scripts/ApplyGrowingSchema.java
```

本次本地环境已执行第三批增量迁移。其他环境仍需自行升级；已有不同结构的同名表应先人工核对。
