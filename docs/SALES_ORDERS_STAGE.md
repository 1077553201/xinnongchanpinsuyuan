# 销售订单与实际出库阶段记录

更新时间：2026-10-22。承接 [库存台账](INVENTORY_LEDGER_STAGE.md)，本阶段接入销售订单、多明细、分次销售出库及库存关联，继续推进 [生产到销售规划](PRODUCTION_TO_SALES_AGENT_PLAN.md) 阶段 2。

## 操作流程

管理台新增“销售订单”（`/admin/sales`）；仓库货物行也提供“建立销售订单”入口，可预填包装来源与仓库，不自动填写数量或价格。

1. **建立订单：** 选择机构，填写订单编码、实际下单日期、客户、收货地址、可选联系方式和说明。通过仓库选择器搜索、分页选择在库货物，一单可包含 1–50 条明细。
2. **填写明细：** 指定包装来源、仓库、完整包装件数及人民币元/件单价。允许明确填写零价；同一包装与仓库合并为一条，同单对同批包装的合计不得超过实际包装件数。下单不扣减或预占库存，不能据此保证已锁货。
3. **登记实际销售出库：** 在具体订单明细下填写实际件数、办理时间、现场人员、说明及可选凭证引用。仓库和客户由订单确定，保存时同时核对订单剩余订购量及该仓该批实际库存。
4. **停止剩余部分：** 尚未出库时可取消；部分出库后可停止余量，填写原因。已出库事实与库存流水保留，不自动退货、退款或退回库存。

订单确认保存后，客户、明细、单价等原始内容当前不可编辑。修改、更正及退货流程后续独立接入，不能通过重建一单掩盖原始履约事实。

## 状态和金额

| 内部状态 | 页面含义 |
| --- | --- |
| OPEN | 待出库 |
| PARTIAL | 部分出库 |
| FULFILLED | 已全部出库，不代表送达或收款 |
| CANCELLED | 出库前取消 |
| CLOSED | 停止未出库部分，保留已出库记录 |

金额固定为人民币，后端按十进制定点数计算，单价最多两位小数。页面预览按“分”精确累加，金额响应使用字符串避免大额浮点精度丢失。订单总额是原始约定金额，不是已收款、实际收入或取消后的应收余额；本阶段不处理税费、运费、收款及结算。

## 库存、来源与可靠性

- 销售出库调用现有库存业务服务，在一个事务内保存库存 OUT 流水、销售关联和订单状态。库存不足时不产生履约记录，避免分别保存造成订单与库存不一致。
- 订单明细数量在取得订单锁后首次读取，防止会话缓存复用锁前数量；库存仍按地块、周期、包装的现有锁顺序检查。真实并发验证覆盖同一订单以及不同订单争用库存。
- 建单和销售出库均使用确认键与内容摘要识别重试，修改内容不得沿用原确认。销售关联唯一绑定库存流水；停止操作保留原因并支持相同原因的重复核对。
- 每条明细保留产品、品种、包装、仓库与规格快照，可回查种植和采收来源；库存流水也能回到对应销售订单。现场办理人与登录录入人分别留档。
- 管理员可跨机构，生产人员限本机构，只读人员仅查看。订单、来源与仓库必须同机构，客户资料不接入公众溯源接口。
- 普通库存出库继续可用，但销售订单履约应从销售页面办理。库存弹窗和销售出库弹窗均提示：不要为同一次销售另行重复登记普通出库。

订单列表支持搜索、状态和后端分页；订单详情完整显示最多 50 条明细，销售出库记录显示最近 200 条，状态及已出库数量覆盖全部关联记录。

## 升级与范围

新环境完整 `database/schema.sql` 已同步；已有环境先完成前五批迁移，再执行 `database/migrations/006_sales_orders.sql`，仅新增订单、明细、销售出库关联三张表。本地已应用迁移，没有重置原业务或把旧普通出库自动关联到订单。

也可从根目录使用已有 Java 11 和 JDBC 驱动，连接信息读取本地 `.env`：

```powershell
& '<Java 11目录>/bin/java.exe' '-Dfile.encoding=UTF-8' -cp '<mysql-connector-java.jar路径>' scripts/ApplySalesSchema.java
```

本阶段尚未提供客户独立档案、订单审核、库存预占、退货退款、更正冲销、运输任务、消费者签收、销售赋码及新业务上链。只管理完整包装，不支持拆箱称重销售。不要将“已全部出库”视为完整销售运输链路已经验收。
