# 来源质检报告与附件实施记录

更新：2026-10-25。本批继续批次 B 的 NEXT-08，建立新采收/包装业务的报告留存、公开核对与附件权限。

## 办理路径与适用来源

- 采收详情点击“查看采收质检报告与附件”，登记本次采收的样本报告；具体包装行点击“查看包装质检报告与附件”，登记本批包装的样本报告。
- 报告记录编号、报告记载机构、采样/检测日期和原记载结论，必须附 PDF、PNG 或 JPG。采收报告的采样不能早于采收日期，包装报告不能早于包装日期；检测日期不能早于采样或晚于今天。种植期土壤等报告不在本批食品样本范围。
- 报告资料与原件同事务保存。默认待核对且附件私有；原资料不覆盖，录入错误可撤回并重新登记。相同来源和相同资料摘要不重复登记。
- 经营方核对后可以公开元数据，附件下载默认仍关闭。公开原件须另勾选隐私核对；上传人与核对公开人分别留档，二者可为同一有权账号，不能因此称为第三方独立审核。
- 撤回须填写原因。此前公开过的记录仍供消费者查看，并保留原记载结论；停止后续公开附件下载，私有附件与审计保留。已下载副本无法收回。

采收样本报告可展示在该采收来源的包装码下，明确标注“原采收批次样本报告”；包装样本报告仅关联该批包装。不会扩散到同产品的其他采收批或其他包装。报告采样结论不是逐件检测承诺。

## 文件、摘要与权限

- 附件最大 5 MB。按文件头/尾识别 PDF，按签名和图片元数据校验 PNG/JPG，并限制图片不超过 1600 万像素；扩展名须与识别格式匹配，不相信浏览器声明的 MIME，不接收 HTML/SVG。
- 原件存放于 MySQL 独立 `MEDIUMBLOB` 表；列表只读取资料，下载才读取原件。数据库备份应同时包含资料表与附件表，无需额外配置本机文件目录。
- 原文件字节计算 SHA-256；规范化资料摘要绑定适用范围、采收/包装身份、报告字段及文件摘要/大小/类型。发布、列表及下载核对已登记摘要；文件缺失或字节变化时停止公开/下载。
- 下载统一经受控接口，返回附件方式、`no-store`、`nosniff` 和沙盒头。管理下载要求登录且通过机构权限；公众下载要求报告仍公开、附件明确允许公开，并核对当前码的实际来源。撤回或不同来源访问不能取得文件。
- 公众只返回经营方核对过的报告字段、范围、摘要与状态，不返回上传人、核对人员、原文件名、撤回私有原因或存储内容地址。公众最多展示最近 50 份，并同时给出总数与截断提示。

本批 `NOT_SUBMITTED` 表示报告及文件摘要均未单独上链，不修改已冻结生产或流转版本。检测结论由经营方按原报告录入；文件格式检查不验证签发机构、数字签名、检测参数或文件安全扫描。报告登记/公开不自动放行、冻结库存、停售或发起召回。

旧 `quality_report` 表不自动迁入新来源，通用旧码保留原展示；新包装码只展示明确关联并核对公开的新报告，不根据产品名称或旧批次标签推断报告适用范围。

## 接口与升级

- `GET/POST /api/production/harvests/{id}/quality-reports`，以及 `packings/{id}/quality-reports`：分页查看、完整登记报告；POST 使用 multipart，`report` 为 JSON 部件，`attachment` 为文件。
- `POST /api/production/quality-reports/{id}/publish`：确认资料摘要、元数据核对与附件公开范围。
- `POST .../{id}/withdraw`：填写撤回原因，保留原公开记录。
- `GET .../{id}/attachment`：机构内私有下载；公众接口为 `/api/public/trace/{code}/quality-reports/{id}/attachment`。

已有环境执行 `database/migrations/014_source_quality_reports.sql`；新环境完整 `database/schema.sql` 已同步。辅助脚本 `scripts/ApplySourceQualitySchema.java` 从忽略的 `.env` 读取配置，仅新增资料和附件两张表，不输出凭据。本机已应用；部署新代码前也需升级。默认上传限制 5 MB、完整请求 6 MB。
