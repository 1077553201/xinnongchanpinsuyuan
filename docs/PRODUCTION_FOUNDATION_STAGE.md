## 本批范围

这是生产业务改造的首批可运行功能，不代表规划中“生产与监测基础”整个阶段已经完成。

- 增加地块登记、查询、筛选和分页，登记所属机构、编码、位置、亩数及负责人。
- 地块开启种植周期，选择同机构有效产品，记录本轮品种、实际种植日期、预计采收日期、负责人和环境要求备注。
- 将本轮产品名称和品种保存为快照，查询历史不依赖产品当前名称。
- 结束本轮需填写日期和说明，并人工核对结束条件。结束后释放地块，历史保留，可再次开启种植。
- 开始与结束操作使用事务和地块行锁；数据库唯一约束保证同一地块仅有一个进行中的周期。拒绝错误日期、重叠历史、跨机构产品和重复编码。
- 工作台优先呈现地块与当前种植，保留原有产品、设备、标签和链上查询入口。
- AI 页面按新规划说明“长文本整理—核对—确认—执行—回执”，明确尚未接入，未提供模拟对话或执行能力。

## 外观

后台顶部“外观”提供两种选择：晨光绿（保留原风格，默认）、柔光玻璃（新增）。选择保存在浏览器本地，刷新后保留，并同步到同源其他标签页。

柔光玻璃采用珍珠白、浅灰绿、少量冷色与暖色柔光背景，半透明功能表面、细高光边缘和柔和阴影，标题采用系统无衬线字体。表格、文字和业务状态保持清晰。减少透明度偏好使用实色表面；浏览器不支持背景模糊时有实色回退；原有减少动效支持继续生效。

## 数据与接口

新增 `farm_plot` 和 `planting_cycle`；不替换既有 `product_batch`，不自动将旧批次、设备或传感器记录归入种植周期，不进行历史来源推断。

新环境使用 `database/schema.sql`。已有环境仅执行 `database/migrations/001_production_foundation.sql`；也可在仓库根目录按 README 运行 `scripts/ApplyProductionSchema.java`，使用本地 `.env` 和已有 MySQL 驱动。脚本仅接受两张新表的建表语句，不修改已有业务记录。`CREATE TABLE IF NOT EXISTS` 不会修复同名旧表的字段差异，已有同名表时需先人工核对结构。

| 方法 | 接口 | 用途 |
| --- | --- | --- |
| GET | `/api/production/organizations` | 查询有效经营主体 |
| GET / POST | `/api/production/plots` | 查询 / 登记地块 |
| GET | `/api/production/cycles` | 查询种植周期与历史 |
| POST | `/api/production/plots/{id}/cycles` | 开启种植 |
| POST | `/api/production/cycles/{id}/end` | 结束种植 |

页面入口：`/admin/production`。编码使用字母、数字、短横线或下划线；地块和种植编码分别全局唯一。日期按当前本地研发环境解释，正式部署前需统一业务时区。

## 已完成验证

- 前端现有 27 项测试通过，TypeScript 检查与生产构建通过。
- 后端 41 项测试通过，其中新增 7 项生产服务测试，覆盖重复种植、机构边界、产品和日期校验、历史重叠、结束及快照保留。
- 已向本机 MySQL 增量创建两张表，没有修改既有业务记录；实际前后端已能够读取新接口。
- 本机 Chrome 使用实际表单完成登记地块、开启种植、确认结束，并验证新一轮保留旧档案。
- 真实接口拒绝重复地块编码和已有活动周期的重复种植；对同一空闲地块同时提交两次开启请求，实际仅创建一个活动周期。
- 外观切换及刷新持久化、减少透明度模式、桌面与手机布局共形成 14 项浏览器检查，无未处理脚本异常。
- 已人工查看桌面地块页、手机地块页和工作台截图；1440px 与 390px 视口检查未发现页面横向溢出。

截图及本机验证结果位于忽略目录 `.workbuddy/preview/production-foundation/`。联调数据以 `QA-PROD-*`、`QA-GROW-*` 编码和“联调测试”名称标记，不代表真实农产生产。测试覆盖一块地的两轮种植，一轮结束、一轮进行中。本批未调用新增业务上链或设备运动控制。

复核步骤：进入“地块与种植”登记测试地块，选择同机构产品开启种植，查看档案，填写结束说明并确认，再开启下一轮；旧档案应继续可见。同一地块在种时再次开启应失败，早于历史结束日期的开始时间应被拒绝。

## 边界和下一步

- 账号认证、机构数据隔离及真实责任人身份尚未实施，负责人仍为人工填写姓名，本环境仍用于本地研发联调。
- 本轮环境要求是文字备注，未配置品种级监测规则，也不会自动更改现有设备告警阈值。
- 带时间范围的设备绑定、巡检任务归属和原始环境数据关联尚未实施；设备当前绑定不能作为历史种植来源。
- 采收、包装、库存、销售、运输任务尚未接入新模型，因此结束条件目前靠人工核对，不能宣称系统已自动检查完所有待办。
- 新地块和种植记录暂未接入链上存证和公众溯源关系；原有扫码和链核验能力继续按原模型运行。
- Agent 的权限、版本确认、幂等执行与部分失败恢复尚未实现。

下一批优先补齐身份权限和设备绑定历史，再落地监测归属与农事记录；Agent 操作清单和共用业务服务随这些规则同步设计。采收包装与库存销售按总体规划后续接入。
