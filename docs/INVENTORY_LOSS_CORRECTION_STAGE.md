# 库存损耗数量更正与影响预览

实施日期：2026-10-26。对应 `NEXT-07` 正规数量更正首批；不是所有单据的通用编辑器。

## 入口与业务边界

进入“库存台账 → 按种植来源查看 → 具体包装库存”，在原 `LOSS` 流水点击“更正数量 / 查看调整历史”。只读账号可查看，写入须具备本机构业务权限。

本轮仅支持原普通库存损耗件数录错的核实调整。填写**更正后的该单损耗总件数**，不是增减差额；允许为 0，不允许负数、无变化或超过系统数量范围。原损耗记录、原件数、净重、人员和时间保留，每次确认追加独立调整单，最多 100 版。

示例：原损耗 3 盒，核实应为 1 盒，则调整后有效损耗为 1，当前同仓库存增加 2 盒。再次核实为 2 盒时，新增下一版、当前库存减少 1 盒，不覆盖上一版。增加可售余额前必须实际核实该货仍属于本仓普通库存，不能把拒收退回或隔离货物借此放行。

## 影响预览与确认

- 预览列出原单摘要、上一版本、原/新有效损耗、库存变化和调整后余额；同时展示同包装来源订单明细、包装码、既有生产/流转/质检证据处理状态。
- 原损耗未绑定具体单品码，因此关联码只是同来源清单，不宣称某个码已损耗。下游记录不会随调整自动改写；证据清单不是本轮实时查链核验。
- 单类关联最多 200 条，超出则拒绝预览和执行，不能用截断清单冒充完整核对。
- 确认内容冻结数量、核实人员、核实时间、原因、参考单据与预览摘要。保存前锁定包装行并重新计算；库存、版本或关联变化时要求重新预览。相同确认标识重试不重复调整，变更内容不能沿用旧标识。
- 保存原单摘要、影响快照与逐版前序摘要，校验历史连续性、数量和内容一致。登记账号与实际核实人员分别留档。

## 库存与证据处理

迁移新增 `inventory_loss_correction` 调整表，以及 `inventory_effective_movement` 当前有效流水视图。原 `inventory_movement` 不改写，不制造虚假 `IN` 入库。

来源台账、分仓余额、仓库明细及整仓分类汇总统一按最新有效损耗计算；累计入库、销售出库仍沿用原事实。普通入出库与更正使用同一包装锁，避免调整后超卖；新流水实际时间不能早于该仓最近原操作或调整登记时间。调整单按当前登记生效，保留核实时间，不提供任意历史时点库存重算报告。

更正后的本仓余额不得为负或超过来源实际包装量，总余额不得超过实际已入库数量。不会修改订单、运输、逐件收货、隔离处置、标签身份或已冻结证据，也不自动发链交易。当前公众生产和流转事实未包含普通库存损耗，本调整不会把未存证的库存调整显示为已验证。

## 部署与验证

已有库先依次完成此前迁移，再执行 `database/migrations/019_inventory_loss_correction.sql`，或在根目录用 Java 11 与本机 JDBC 驱动运行 `scripts/ApplyLossCorrectionSchema.java`；脚本从忽略的 `.env` 读取配置。新库 `database/schema.sql` 已同步。应用账号读取库存须能访问该视图；升级前备份，完成迁移再部署本版，无需重部署合约。旧代码忽略调整会算错余额，存在调整记录后不能单独回退为旧库存查询。

- 467 项后端测试、40 项前端测试及前端构建通过；覆盖增减/归零、超量、版本变化、重放、权限、历史摘要、核实时间和预览范围。
