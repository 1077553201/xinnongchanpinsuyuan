# 日常助手：连续对话与业务办理

日期：2026-10-22。

## 使用方式

AI 助手首页改为日常聊天，保留晨光绿 / 柔光玻璃主题。可以问种植问题、查业务、补充刚才的情况，也可以粘贴长段现场记录，无需先写日报。

- “现在有哪些地块在种植？”：按当前机构查询，回复下方展示查询来源和业务页面入口。
- “看看某仓库有哪些现货”：先确定仓库，再查库存。查询有条数上限，不能代表全库统计。
- “刚采收了……帮我登记”：生成操作单，打开后核对、补齐、勾选并明确确认才执行。
- “刚才那项人员写错了”：可提出替代清单；仅未成功执行、事项数量一致的待确认清单可被替代，旧单随后禁止确认。成功业务不能通过改聊天覆盖。

历史对话按账号私有保存，同机构其他账号也不能读取。桌面左侧切换对话，手机通过“对话记录”弹窗切换，主导航仍从右侧展开。Enter 发送，Shift + Enter 换行。原手动整理与回执入口保留在“操作单与执行记录”。

## 能力与边界

只读工具覆盖地块、种植周期、仓库、库存、销售、运输、农事、环境异常和采收。服务端固定机构范围，不接受模型指定机构或任意 SQL。结果每次最多 10 或 20 条，每轮回答最多六次查询。无查询结果时不能声称已掌握业务事实。

实际写入工具目前只有采收和运输事件，其他事项可以交流或列为待办。聊天中的“确认”不会调用执行接口。只读账号可以聊天和查询，不能创建待执行业务或确认写入。

完整消息保存在数据库，界面每批加载 30 条；模型使用最近八轮已完成上下文，用户原文合计最多 12,000 字符，不等于无限记忆。普通聊天不预先发送整套业务资料，需要查询时才带入必要结果。外部模型会接收本次消息、有限上下文和必要查询结果；本轮已取得用户明确授权。数据库密码、模型密钥和区块链私钥不进入对话内容。

回复完成后整体显示，尚未实现逐字流式输出、附件和语音。失败可重试原消息；请求标识去重、三分钟处理租约和状态检查避免重复消息及过期回复覆盖。查询与拟稿不执行采收或库存变动。

## 配置与升级

已有库完成前八批迁移后，执行 `database/migrations/009_agent_conversations.sql`，或用 Java 11 和 MySQL JDBC 驱动运行 `scripts/ApplyChatSchema.java`，连接参数从本地 `.env` 读取。只新增两张表，不重置业务。全新部署使用已同步的 `database/schema.sql`。

日常对话需设置 `AI_PROVIDER=compatible`、`AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`，并重启后端。未启用时明确提示，不把规则整理冒充自然对话。默认使用 `Authorization` 和 `max_tokens`；MiMo 配置为 `AI_AUTH_HEADER=api-key`、`AI_TOKEN_PARAMETER=max_completion_tokens`。密钥只放忽略的本地配置。

配置依据：[MiMo Token Plan 接入](https://mimo.mi.com/docs/zh-CN/tokenplan/Token%20Plan/quick-access)、[结构化输出](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/text-generation/structured-output)。

## 本轮验证

后端单元测试覆盖对话归属、只读权限、消息重试、处理中互斥、查询依据、查询预算及非法操作类型；前端执行状态测试与生产构建。真实 MiMo 联调通过连续追问、同请求去重、业务查询、生成采收清单、修改后旧单失效、拒绝旧单确认、聊天确认不执行及只读账号限制。使用 QA 数据生成待确认清单，未执行实际采收或库存变动。

设备管理与设备读数既有问题仍按待优化清单后续处理。

最终检查：后端 201 项测试、前端 31 项测试及生产构建通过。浏览器已验证真实消息收发、刷新后历史保留、新旧操作单弹窗、只读旧单提示、修改后的人员字段、主题切换和手机历史弹窗；320–1920 像素宽度检查无页面横向溢出，390 像素手机输入区位于可视范围内。截图接口超时，未完成截图视觉验收，不能将布局测量视为完整视觉验收。

联调保留 `QA-CHAT-*` 对话及关联待确认操作单，均为软件测试记录，不代表真实采收或设备采集。
