# 农产品可信溯源系统项目目标

最后更新：2026-07-07

## 项目定位

建设一个面向真实农产品生产、流通和消费查询的可信溯源系统。系统以单品级二维码和 NFC 作为查询入口，以真实硬件传感器数据提升生产阶段可信度，以 FISCO BCOS 3.11 联盟链保存关键摘要证据，并预留后续向公有链做二次存证的能力。

本项目不是只做展示页，而是要形成可持续研发的工程基础：后端、前端、合约、数据库、设备接入、AI 助手和部署文档都要围绕同一个目标推进。

## 核心目标

- 单品级溯源：每件农产品生成唯一 `traceCode`，二维码和 NFC 都指向同一个公众查询页面。
- 生产阶段可信采集：在农作物生产阶段接入真实硬件传感器，通过网关和 MQTT 记录温度、湿度、光照、土壤环境等生长数据。
- 链上摘要存证：FISCO BCOS 3.11 负责保存批次、单品码哈希、事件哈希、传感器数据窗口哈希、操作者和时间等摘要信息。
- 链下业务明细：完整业务数据、传感器原始数据、质检报告、图片和附件保存在数据库或对象存储中。
- 二维码和 NFC 共存：消费者扫码或 NFC 触碰后进入同一套查询结果，页面展示标签绑定状态和链上校验状态。
- AI 双端能力：面向农场管理人员提供农场助手，面向消费者提供用户助手。
- 公有链预留：后续支持把联盟链摘要或 Merkle Root 锚定到公有链，作为更开放的外部存证。

## 技术路线

- 区块链：本地已部署的 FISCO BCOS 3.11 节点。
- 合约：先完成农产品溯源核心智能合约 `AgriTrace.sol`，手动部署到本地 FISCO BCOS 3.11 节点后，再把 ABI、bin、Java wrapper、合约地址和部署交易信息拉回仓库。
- 后端：克隆 FISCO 官方 Maven SpringBoot 示例 `spring-boot-crud` 作为基础；后端业务接口必须围绕已部署合约的真实接口、事件和返回值适配，使用 Java 11。
- 前端：Vue 3、TypeScript、Composition API、`<script setup lang="ts">`。
- 数据库：MySQL 8，开发阶段使用现有账号连接。
- IoT 接入：边缘网关加 MQTT，开发阶段优先使用本地 EMQX/Docker。
- AI 接入：后端保留可替换的 `AiProvider` 接口，先实现助手服务边界，再决定具体模型供应方。
- 官方后端模板：优先从 `https://github.com/FISCO-BCOS/spring-boot-crud.git` 克隆；网络慢时使用 `https://gitee.com/FISCO-BCOS/spring-boot-crud`。
- 合约生成：优先使用 FISCO 控制台 `contract2java.sh` 生成 Java 合约包装类。

## 业务范围

V1 覆盖完整溯源闭环：

- 产品与批次管理。
- 单品码生成、打印和绑定。
- NFC 标签绑定与查询入口校验。
- 生产阶段传感器接入、生长环境曲线和异常告警。
- 农事记录、采收、加工、质检、仓储、物流、到店、销售和召回事件。
- 公众扫码/NFC 查询页。
- 后台链上交易回执和哈希一致性校验。
- 农场管理 AI 助手和消费者 AI 助手。

V1 不直接实现：

- FISCO 链节点部署。
- 公有链真实交易发送。
- AI 自动下发设备控制命令。
- 把传感器原始连续数据完整写入链上。
- 把数据库密码、私钥、证书正文写入仓库。

## 可信数据策略

链上只保存可验证摘要，链下保存可查询明细：

- `batchId`：批次唯一标识。
- `itemCodeHash`：单品码哈希，不直接暴露原始码。
- `eventType`：业务事件类型。
- `eventHash`：事件明细规范化后的哈希。
- `sensorWindowHash`：某个设备或地块在固定时间窗口内的传感器数据摘要。
- `operator`：链上操作者地址或系统账户标识。
- `timestamp`：业务时间或链上记录时间。
- `txHash`、`blockNumber`、`receiptStatus`：交易追踪字段。

前端查询时展示“链上已验证事实”和“AI 建议/解释”的边界，避免把 AI 推测当作已存证事实。

## IoT 与 NFC 目标

传感器数据流：

```text
传感器 -> 边缘网关 -> MQTT Broker -> 后端 IoT 接入服务 -> MySQL 明细 -> 数据窗口摘要 -> FISCO 摘要存证
```

默认 MQTT topic 规划：

```text
agri/{farmId}/{gatewayId}/telemetry
agri/{farmId}/{gatewayId}/status
agri/{farmId}/{gatewayId}/event
```

NFC 查询目标：

- NFC 标签与单品码建立绑定关系。
- 扫码和 NFC 都打开 `/t/{traceCode}`。
- 查询页展示 NFC 状态：已绑定、未绑定、标签不匹配、疑似异常。
- V1 先做统一查询体验，后续可升级为带动态签名的防克隆 NFC 标签。

## AI 目标

农场管理助手：

- 汇总传感器趋势和异常告警。
- 根据批次、地块、设备、质检和事件数据生成管理摘要。
- 辅助回答“某批次最近有什么风险”“哪些设备离线”“哪些产品质检异常”。

消费者助手：

- 基于当前单品真实溯源数据回答产地、生产环境、质检、物流和食用建议。
- 对链上已验证内容给出明确标识。
- 对健康功效、医疗建议、超出产品事实的问题进行限制。

## 前端体验方向

后台界面面向重复工作和管理决策，优先保证信息密度、筛选效率、状态可读性和异常处理效率。

公众查询页面向消费者，优先保证移动端可读性、信任感和清晰事实边界。页面应展示真实产品、产地、环境数据、流转时间线、质检结果、链上校验和 AI 问答入口。

## 后续里程碑

1. 前提准备：落盘项目目标、环境准备清单、`.env.example` 和安全忽略规则。
2. 智能合约优先：生成 `contract/AgriTrace.sol`、合约接口说明、部署清单和后端适配清单。
3. 手动部署合约：用户将合约部署到本地 FISCO BCOS 3.11 节点，并把 ABI、bin、Java wrapper、合约地址和部署交易信息拉回仓库。
4. 后端适配：基于 FISCO 官方 `spring-boot-crud` 示例改造后端，使 ChainService 按合约真实接口调用。
5. 数据库建模：完成核心业务表、IoT 表、NFC 表、AI 表和链交易表，并与合约事件/状态对齐。
6. 核心闭环：创建批次、生成单品码、追加事件、扫码查询、链上校验。
7. IoT 接入：启动 EMQX，接收模拟网关数据，生成数据窗口摘要。
8. NFC 接入：完成标签绑定、查询入口和异常状态展示。
9. AI 接入：实现农场助手和消费者助手的接口、会话和安全边界。
10. 文档和验收：完善 README、部署说明、演示脚本和测试清单。

## 成功标准

- 任意单品可以通过二维码或 NFC 查询到完整溯源时间线。
- 生产阶段环境数据可由 MQTT 进入系统，并以窗口摘要形式完成链上存证。
- 链下事件和传感器摘要能与链上记录校验一致。
- 后台可追踪每笔链交易的状态、交易哈希和区块高度。
- AI 能基于授权数据回答问题，并明确区分事实和建议。
- 敏感信息不会出现在文档、README 或公开仓库文件中。
