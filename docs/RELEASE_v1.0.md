# v1.0 首个试用版本

发布日期：2026-10-27；Git 标签 `v1.0`，前后端应用版本 `1.0.0`。面向受控试用与软硬件联调，不把此版本标记为田间全链路或生产运维验收通过。

## 已包含

- 地块与种植、环境规则与农事、采收分级包装、库存、销售及运输交付。
- 机构与人员管理、角色范围、机构停启用、依赖删除保护及审计。
- 包装赋码、二维码公众查询、生产/流转/质检版本存证、NFC 关联及回执核查。
- 日常 AI 对话、查询来源和受控操作确认；当前写入工具仍以采收和运输事实为主。
- 启动自动建库建表和空用户库初始管理员；既有记录保留。
- 当前全宽主题、移动抽屉及已有域名开发访问配置。

## 发布文件

- `agri-trace-v1.0-source.zip`：标签对应的已跟踪源码，不含工作区未跟踪笔记。
- `agri-trace-v1.0.zip`：后端可执行 JAR、前端静态文件、初始化/迁移 SQL、EMQX 示例部署、Nginx 配置、启动脚本和说明。
- `SHA256SUMS.txt`：两个压缩包的 SHA-256，用于下载完整性核对。

运行包不包含 `.env`、私钥、证书、数据库备份、真实附件、AI 密钥或设备固件；基础服务和机构经营资料需要自行配置。

## 运行包启动

1. 解压运行包。准备 Java 11、MySQL 8、可达的 FISCO BCOS 节点及自己的 SDK 证书；采样需另外启动 EMQX/网关。当前旧 SDK 初始化依赖可用链节点，即使关闭业务写链也不代表可离线启动整个后端。
2. 将 `.env.example` 复制为 `.env`，填入数据库、FISCO、MQTT 和可选模型配置。设置 `FISCO_SDK_CERT_PATH` 为本机证书目录，`FISCO_PEERS` 使用一个可达节点地址，合约地址和群组需与实际链一致。私密文件不要上传到仓库。
3. 新空库配置 `INIT_ADMIN_USERNAME` 和 12–128 位的 `INIT_ADMIN_PASSWORD`；数据库账号需具备所需建库/建表/建视图权限。已有旧版本数据库先备份并按迁移说明升级，启动建表不会自动补旧表缺失字段。
4. 在解压目录运行 `powershell -ExecutionPolicy Bypass -File .\Start-Release.ps1`，启动后端 8080。`-CheckOnly` 只检查本地配置、Java 和 JAR，不启动服务。
5. 使用已安装的 Nginx 托管前端。在解压目录执行 `nginx -p "解压目录绝对路径/" -c nginx.conf`；目录中已有 `logs/`。示例监听 5173，代理 `/api` 至 8080，支持管理页面和扫码页面刷新。先释放占用同一端口的 IDE/Vite 服务；更改后端端口时同步改代理。
6. 浏览器访问 `http://本机地址:5173`，手机使用可达的局域网地址。设置 `PUBLIC_TRACE_BASE_URL` 为实际扫码入口，例如 `http://局域网地址:5173/t`；`0.0.0.0` 是监听地址，不是扫码地址。

Nginx/Java/MySQL/FISCO/EMQX 不随 ZIP 附带；源码运行仍按主 README。参考 Nginx 配置需要在目标环境校验，HTTPS、域名和防火墙按实际部署设置。

## 已知限制与验收边界

真实传感器、检测车任务与采样归属、设备验签/去重、实物 NFC 和田间全链路仍需按 [首版验收清单](FIRST_TRIAL_RELEASE_PLAN.md) 推进。待发运运输撤销/替代的新增持久化 QA 验收尚待办理，高阶售后和部分 Agent 工具未完成。具体缺口见 [未完成模块报告](UNFINISHED_MODULES_REPORT.md)。

版本基线已有后端 564 项、前端 40 项检查及构建验证、机构独立 MySQL 联调和只读浏览器复核。发布封装另检查版本一致性、JAR/静态资源及不夹带本地私密文件；这些检查不替代新电脑完整部署验收。
