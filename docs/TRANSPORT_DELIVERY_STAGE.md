# 运输与交付阶段记录

更新时间：2026-10-22。承接 [销售订单](SALES_ORDERS_STAGE.md)，继续推进 [生产到销售规划](PRODUCTION_TO_SALES_AGENT_PLAN.md) 阶段 2。

## 入口与流程

管理台新增“运输与交付”（`/admin/transport`），支持搜索、状态筛选和后端分页。建立运输安排须从销售订单详情的**实际销售出库记录**进入；未出库订单不能直接生成已发货事实。

1. **建立运输安排：** 填写运输单编码、承运方、承运联系人，可填写运单号或车辆标识、联系方式和说明。收货方、地址、货物来源与件数沿用原销售记录，保存后状态为“待发运”。
2. **登记实际发运：** 明确实际时间、地点、现场人员、情况说明和可选凭证引用，保存后才进入“运输中”。
3. **追加进展或异常：** 按实际发生顺序记录，原记录保留。异常描述不自动表示问题解决、温度恢复或实物合格。
4. **登记收货结果：** 分别明确填写整数实收和拒收件数，合计必须等于本笔实际出库件数。全部实收为“已全部接收”；存在拒收为“收货有拒收”。收货结果保存后结束本单运输记录。

每笔实际出库整批关联唯一运输单。本阶段不支持把同一笔出库再拆成多车；需要分批运输时，应先分别登记销售出库。停止订单未出库余量不妨碍已经出库部分继续登记运输。

## 业务与数据边界

- 运输不再次扣库存；拒收不自动退库、退款、建立退货或改变销售出库完成状态。实物退回须在后续独立退货业务中核对。
- 运输安排和已登记事实当前不可编辑、撤销或覆盖；更正、承运方变更、转运及分次签收后续独立接入，不通过重复建单掩盖原记录。
- 实际发运时间不能早于销售出库；后续事件不能早于上一条事件或晚于当前时间。现场办理人、系统录入人与录入时间分别留档。
- 使用订单锁串行化同一来源的运输建单，用运输单行锁串行化事件确认；状态首次读取放在取得行锁之后，避免 MyBatis 会话缓存复用旧状态。唯一来源关联、确认键和内容摘要共同防止重复建单、重复发运或重复收货。
- 管理员可跨机构，生产人员限本机构，只读人员仅查看。客户地址和承运联系方式仍为后台资料，不进入公众溯源接口。
- 详情显示最近 200 条运输事实；状态、时间下限与收货校验基于完整数据。所有事实与操作审计同事务保存。

## 升级

已有环境完成前六批迁移后，执行 `database/migrations/007_transport.sql`，仅新增 `transport_shipment`、`transport_event`。新环境完整 `database/schema.sql` 已同步；启动程序不会自动执行迁移或示例数据。

也可从根目录用现有 Java 11/JDBC 驱动运行：

```powershell
& '<Java 11目录>/bin/java.exe' '-Dfile.encoding=UTF-8' -cp '<mysql-connector-java.jar路径>' scripts/ApplyTransportSchema.java
```

本机已应用增量迁移，保留原业务数据；旧销售出库不会自动生成运输安排。
