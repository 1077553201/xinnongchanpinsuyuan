# 启动自动建表与初始管理员

后端默认开启初始化，适用于 IDE、启动脚本及打包后的应用。启动脚本读取根目录 `.env`；IDE 和直接运行 JAR 时仍需配置对应环境变量。

## 首次启动

配置 MySQL 连接和 `DB_NAME`，并在本地环境设置：

```dotenv
DB_CREATE_DATABASE=true
DB_INIT_ENABLED=true
INIT_ADMIN_USERNAME=admin
INIT_ADMIN_PASSWORD=填写自己的12至128位密码
```

启动后端即可。MySQL 账号需要相应数据库的建表、建视图及读写权限；数据库不存在时还需建库权限。若数据库由运维预建，设置 `DB_CREATE_DATABASE=false`。初始化脚本始终使用连接配置的数据库，不切换到固定的 `agri_trace`。

## 初始化范围

- 使用随应用打包的 `database/schema.sql` 创建缺失表、视图和基础角色，不导入示例产品、设备、库存或链记录。
- 仅在 `sys_user` 完全为空时，创建初始机构 `ORG-INITIAL`、管理员和 ADMIN 角色关联；使用现有密码哈希算法，不保存或输出明文密码。
- 已有任何用户时跳过账号初始化，不提升权限、不重置密码、不重新启用停用用户。没有管理员的旧库仍需显式维护，不借启动恢复权限。
- 重启使用幂等建表与基础数据操作；MySQL 初始化锁串行保护多个实例首次初始化，管理员及角色关联在同一事务中保存。
- 表和账号初始化先于 MyBatis 与 MQTT 订阅。错误会阻止应用完成启动；DDL 可能已部分完成，修正配置后可重试。

空用户库未配置合格密码时会明确报错，不使用通用默认密码。修改已初始化账号的密码请使用已有账号管理流程，改变初始密码配置不会重置账号。

## 已有数据库

不会删除表、清空经营数据或覆盖用户。`CREATE TABLE IF NOT EXISTS` 不会替旧表补缺失列，旧版本升级仍按对应迁移说明办理；本次不引入全版本自动迁移。初始化会刷新仓库定义的视图并回填缺失的运输计划快照，启动前应确保已有库迁移到兼容结构。

如由运维完全管理结构，可设 `DB_INIT_ENABLED=false` 关闭表及账号初始化，并按需同时关闭自动建库。启用初始化的数据库账号需允许创建/刷新视图。

验证范围仅为初始化：空库建表、初始管理员、再次启动不重复、不重置密码及失败回滚，不扩测其他模块。
