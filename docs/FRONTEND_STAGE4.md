# 前端第 4 阶段：公众查询与实时链上核验

日期：2026-10-20。

- 公众查询现在通过 `ChainService` 读取 FISCO 的批次、单品和事件摘要；重新计算当前业务字段摘要，按事件 ID 匹配链上记录，不依赖时间线顺序。
- 同时检查链上事件数与业务记录数，避免业务事件被遗漏后仍显示完整通过。
- `verificationSource: LIVE_CHAIN` 才允许通过结论；读取失败或超过单次 200 条事件验证上限时为 `UNAVAILABLE`，保留业务查询能力，但不把数据库保存的成功结果当成实时证据。
- 上链交易状态、实时摘要核验和产品质量分别展示。链上召回状态会触发公众页召回提示，不能被数据库中的正常状态覆盖。
- 环境窗口查询改为按当前单品所属 `batch_id` 过滤；不再混用全局近期采样。页面明确展示「本批次环境记录」。环境窗口的交易确认状态不等同于逐窗口实时摘要核验。

## 验证

前端 26 项回归测试与生产构建通过。后端覆盖实时摘要匹配/不匹配、节点异常、业务时间线遗漏链事件及按批次查询环境。

对已有 QA 单品 ID 1、2 的真实 GET 查询均返回 `LIVE_CHAIN`，批次和单品摘要匹配；单品 ID 2 的采收事件摘要也匹配。浏览器确认移动端标题与印章显示「链上摘要核验通过」，无横向溢出；模拟节点不可用响应后改为「链上核验暂不可用」，不会重用成功文案。本阶段没有创建链交易或改动业务数据。

后续扩展应处理大规模事件的分页核验及公开查询限流；当前查询会实时读取最多 200 条链事件，不提供批量核验完成的虚假结论。
