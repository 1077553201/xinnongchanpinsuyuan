## 本批行为与入口

在“采收与包装”选择原种植周期，打开采收详情，从具体包装批次点击“查看来源与包装赋码”。

- 沿用当前完整包装模型：**一码对应一件完整包装**，例如一盒、一袋或一箱，单件净重使用包装记录的实际值。用户勾选规格确认后生成，不支持拆箱、散装或混批赋码。
- 每次生成 1–100 个码，允许分次办理，累计不能超过该包装的实际件数。赋码不改变库存，不代表已经销售、完成质检或完成实物贴标。
- 显示完整包装数、已赋码数和尚可赋码数；每页展示 20 个码，支持二维码预览和打印本页标签。标签访问地址可填写手机可达的前端地址，只改变预览链接，不修改原码和来源。
- 二维码进入现有 `/t/{traceCode}`，新增展示地块、周期、产品/品种、种植日期、采收、等级、包装时间、包装单位和单件净重。仅展示来源基础，不把尚未关联的环境、农事和运输补造为完整时间线。

## 来源模型与数量约束

来源关系为：`地块 → 种植周期 → 采收 → 可用等级 → 包装 → 单品码`。

新增三表：

| 表 | 用途与约束 |
| --- | --- |
| `packing_trace_batch` | 一个包装关联一个既有通用批次，保存首次赋码时的来源快照和摘要；包装和通用批次均唯一关联 |
| `packing_trace_issue` | 每次确认生成的件数、办理人、请求标识和内容摘要；请求标识全局唯一 |
| `packing_trace_item` | 复用既有 `trace_item`，保存包装、赋码操作及包装内序号；一个单品仅有一个来源，包装内序号唯一 |

来源快照保存为规范化 JSON 文本并计算摘要，读取时核对文本摘要；不能将这个链下自检当作链上验证。公众响应采用字段白名单，不返回人员、联系方式、机构内部编号、存放位置备注或凭据。

赋码事务锁定包装行，再读取完整累计数量并生成关联。相同请求和内容重试返回原码；改变数量或办理人不能沿用同一请求。批次、来源、操作、码及审计同事务保存，无链上外部副作用。打印或刷新不新增码。结束原周期、开启下一季后仍从原包装关联和已保存快照读取来源，不重新归属到新周期。

旧单品记录不自动补来源。旧通用赋码接口拒绝对包装来源批次继续发码，避免绕过数量校验。

## 存证与兼容边界

新包装批次及单品明确使用 `NOT_SUBMITTED`（未提交存证），不创建待执行链交易，不调用合约，不改 ABI、字节码或 wrapper。公众页显示“来源尚未提交存证”，不会显示核验通过；`CHAIN_DISABLED` 继续表示原有禁用场景。

新包装来源暂不能从旧入口关闭/召回通用批次、绑定 NFC 或追加通用链事件，防止生成尚未接入的链上状态或脱离真实业务的事件。原有非包装来源批次及单品继续使用既有流程；完整新业务存证、NFC、召回和公众证据时间线在批次 B 细化接入。

当前码尚未分配到具体销售出库件、运单或消费者，不能凭包装层数量关系断言某个具体码已经发货或签收。实物一码一贴、漏贴、重贴、损坏标签处理仍需试点规则与现场验收。

## 升级

已有库先完成前九批迁移，再执行 `database/migrations/010_packing_trace_codes.sql`。新环境 `database/schema.sql` 已同步。

可用现有 Java 11 和 MySQL JDBC 驱动，从仓库根目录运行：

```powershell
& '<Java 11目录>/bin/java.exe' '-Dfile.encoding=UTF-8' -cp '<mysql-connector-java.jar路径>' scripts/ApplyPackingTraceSchema.java
```

工具从忽略的本地 `.env` 读取连接参数，仅允许本批三条建表语句，不重置旧业务或补造旧来源。本机已应用迁移；旧接口也新增了映射检查，因此部署本版代码前需要完成本批迁移。

## 验证事实

- 后端 215 项测试通过，包括赋码数量、同请求重试、旧入口防绕过、只读与跨机构限制、快照保留、公众字段白名单和快照摘要异常拒绝。
- 前端 33 项状态测试和生产构建通过；新增 `NOT_SUBMITTED` 不得显示核验成功的回归用例。
- 真实 HTTP/MySQL 联调：独立 QA 包装首次生成三件；原请求重试不增发；两笔七件请求竞争余下九件，仅一笔成功；超量、小数和越权被拒绝。21 件分页返回 20+1，汇总覆盖完整数量。
- 真实换季验证：独立 QA 周期结束后开启下一季，再对原周期包装赋码，公众查询仍返回原周期和原品种；不修改真实经营地块或旧产品来源。
- 浏览器实际勾选确认并生成两件，检查规格提示、剩余件数、二维码图片和公众来源页；320、390、768、1440 像素弹窗无整页或弹窗横向溢出；390 像素公众页正常。桌面弹窗及手机公众页已截图并人工查看。
- 标签打印先发现后台渐变及多余空白页，改用独立打印区域后重新导出并渲染检查，两张标签为一页、白色底、二维码与规格文字完整。尚未用实体打印机及实物标签验收。

本次 QA 使用 `QA-CODE-*`，只代表软件测试；截图、打印检查文件及脚本位于忽略的 `.workbuddy/preview/`，未加入仓库。
