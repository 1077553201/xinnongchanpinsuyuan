# 包装码逐件出库与收货实施记录

更新：2026-10-25。本批继续批次 B，补齐具体包装码与实际销售出库、运输及后台收货的关联基础。

## 办理路径

1. 在采收包装页为完整包装赋码，按实物粘贴标签。
2. 销售订单登记实际出库后，在该条记录点击“核对包装码 / 逐件收货”。搜索或扫描包装码，从同来源可用码中勾选，核对确认清单后保存。每页 20 个，可分次关联。
3. 从原出库建立唯一运输单，登记实际发运、进展和收货汇总。运输详情同样提供逐件核对区。
4. 收货汇总保存后，在“本笔出库已关联的码”中分别选择实收或拒收，核对实物后确认。未明确核对的码保留待核对状态，即使整单全部接收也不会自动确认。
5. 消费者扫码后查看本件出库、关联留档时间、运输事实及明确登记的逐件收货结果；原始发生时间与补充核对留档时间分开展示。

## 数量与审计边界

- 同码只能关联一笔出库，须属于该笔出库的包装来源；累计关联数不超过实际出库件数。允许后补关联，但不会把留档时间改写为实际发货时间。
- 所有同来源分配共用包装行锁；逐件收货额外锁运输单。跨出库争抢、超量、重复码和已确认结果覆盖均拒绝。
- 逐件实收、拒收分别不超过原运输收货汇总，尚未关联或尚未核对的数量保持未分配。原库存流水不重复写入，拒收不自动退库或退款。
- 确认标识包含账号、出库、动作、排序后的码集合和结果；原样重试返回原结果，改内容复用标识被拒绝。关联与收货分别留录入账号、时间及审计。
- 公众白名单仅包含时间、运输事件类型及逐件结果，不展示客户、地址、联系方式、办理人员、自由描述或凭证引用。运输事实仅展示最近 200 条并明确截断。

## 接口与部署

- `GET /api/production/sales/dispatches/{id}/items`：同来源码列表，支持 `search`、`mode=AVAILABLE|ASSIGNED|ALL`、`page`；每页 20 个。
- `POST` 同路径：`itemIds`、`requestKey`；每次 1–100 个不同码。
- `POST .../items/receipt`：另加 `outcome=ACCEPTED|REJECTED`。
- 查询、关联及收货均遵守机构隔离；只读账号不能写入。

已有环境执行 `database/migrations/012_item_circulation.sql`；新环境完整建表已同步 `database/schema.sql`。辅助脚本 `scripts/ApplyItemCirculationSchema.java` 从本地 `.env` 读取连接配置，只新增两张表，不输出凭据。本机已应用迁移；部署本版前也需升级，因为包装码公众查询会读取关联表。
