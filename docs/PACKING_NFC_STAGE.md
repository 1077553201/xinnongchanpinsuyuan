# 包装码 NFC 身份与一致查询入口

更新：2026-10-25。本轮继续批次 B 的 NEXT-04，补充新来源包装码的 UID 登记、链上关联、停用及公众核验。NEXT-22 的换绑和动态防克隆不在本批范围。

## 操作路径

采收与包装 → 查看来源与办理 → 查看来源与包装赋码 → 选择具体码的“查看 / 办理本件 NFC 身份”。同机构可查看，有写权限的账号才可确认办理。

1. 完成本码生产来源存证，再输入标签的 4、7 或 10 字节十六进制 UID。空格、冒号、短横线会去除，统一大写后计算 SHA-256；原始 UID 不入库、不上链。
2. 预览本件包装、标签摘要及生产证据摘要，勾选确认后绑定。一次绑定保留原始资料；同 UID 不能分配给另一件，同件不能覆盖或换绑，停用后也不释放原关联。
3. 页面显示二维码产品地址和 NFC 查询地址。用外部标签工具将 NFC 地址写入 NDEF URL，贴到对应实物，再用手机核对。本系统本轮没有读取、烧录或验证实体标签的能力。
4. 标签破损或不再使用时填写内部原因，预览并确认停用。请求留档后立即停止 NFC 自动跳转，链上停用状态独立显示。原绑定、停用原因、操作者和两次交易分别保留，没有恢复入口。

旧 NFC 管理页继续处理旧单品；新来源包装码不再出现在旧绑定候选中，已有包装标签引导到来源包装办理。后端仍阻止旧接口绕过新流程。

旧入口历史 UID 摘要保留原算法输入，无法从摘要还原并自动规范化。已有旧实物标签升级前须人工核对，不能仅凭新旧摘要不同判定是不同标签；本轮未迁移或重新绑定旧标签。

## 同一身份与证据边界

- 二维码使用 `/t/{traceCode}`；NFC 使用 `/n/{uidHash}`，公众接口为 `/api/public/trace/nfc/{uidHash}`。只有实时核验来源、单品、标签归属和绑定摘要一致，且没有停用请求、链上标签仍有效，才自动进入同一个 `/t/{traceCode}`。
- 已停用、待确认、读取失败或摘要不符时保持在标签核验页。已知标签仍提供原关联产品的历史入口；历史可查看不表示标签仍有效。不明标签或没有新来源绑定留档的旧记录不会被推测关联。
- 绑定快照含具体码、标签 UID 摘要、来源及生产证据摘要；停用快照另绑定原始关联摘要和原因摘要。公开数据不含内部停用原因、账号资料或原始 UID。
- NFC 身份和原生产、流转、质检证据分别核验，不覆盖已冻结快照。普通 UID、二维码和静态 URL 可复制；读取 URL 不等于读取实体 UID，也不构成防克隆、实物质量或设备身份验证。

## 提交与恢复

新增操作留档表，按单品与操作类型唯一约束。包装行锁和同码处理租约防止并发确认；RPC 前独立提交操作与交易意图，网络调用不占用长期写事务。每次恢复先查链，已存在且摘要匹配则返回确认，不重复绑定或停用。

结果未知保持 `UNCERTAIN`，原交易未确定时不重发；明确失败回执、链禁用可经重新确认恢复。绑定未确认前不得另建停用操作；停用请求不会因恢复原绑定而清除。长期未知交易的集中对账工作台尚未实现。
