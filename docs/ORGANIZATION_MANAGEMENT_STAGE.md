# 机构管理与全系统归属检查

日期：2026-10-27。范围：补齐机构管理，并检查现有各模块中机构选择、名称展示、权限和状态关联；保留当前主题、全宽布局和移动导航。

## 入口与操作

管理员侧栏新增“机构管理”（`/admin/organizations`），支持名称/编码/联系人搜索、状态筛选、分页、详情、新建、编辑、停用、启用和删除空机构。机构名称、类型、联系人、电话、地址可以修改，编码作为历史身份保留。

人员、产品、地块、仓库、订单与设备分配处可打开机构管理，并刷新已经打开表单的机构选项。产品不再手填机构 ID。新建主体后无需修改数据库或导入示例数据即可继续办理业务。

## 删除与停用

- 机构详情展示 11 类直接关联数量：账号、产品、批次、地块、设备归属、仓库、销售订单、质检报告、退回处置、订单替代和操作审计。种植、农事、采收、包装、库存、运输和证据通过这些来源间接关联。
- 任意历史关联存在时禁止删除；确认时重新查依赖，不只依靠前端按钮。空机构采用逻辑删除，保留原编码与管理审计，不允许复用编码或恢复为另一主体。
- 停用保留历史，移出新建业务选项；所属账号无法登录/继续使用会话，不能创建新的根业务、开启种植或新增绑定。管理员仍可核对和处理原有事实，不自动撤销订单、清库存、解绑设备或修改链证据。
- 重新启用机构不会把单独停用的账号自动启用。当前登录账号所属机构禁止停用/删除；需要处理时应由其他机构的管理员登录。
- 机构类型仅描述经营主体类别，不自动授予权限；管理员仍管理全部机构，生产人员/只读人员仅能访问所属机构。

## 全系统检查与修复范围

| 模块 | 检查及处理 |
| --- | --- |
| 机构档案 | 新增完整管理入口、接口、关联查询及操作审计，不增加新表 |
| 人员账号与登录 | 新建校验启用机构并加锁；历史名称包含停用机构；既有会话校验继续检查机构状态 |
| 产品与旧批次 | 产品改为机构下拉；后端补有效性校验与机构锁；批次沿用同机构产品，停用机构不能创建批次或发送注册交易 |
| 地块与种植 | 有效机构选择和名称展示；登记/开启种植重新锁定核对；产品保持同机构限制 |
| 环境与农事 | 按周期→地块检查归属；补机构名称；人员候选只包含启用机构内的有效可作业账号 |
| 采收与包装 | 沿用周期→地块来源权限，补经营主体展示；不增设可任意换机构的输入 |
| 库存与仓库货物 | 登记仓库只选有效机构，保存时锁定检查；旧仓和分仓货物展示停用机构名称；保留同机构包装来源检查 |
| 销售、替代与运输 | 新建订单核对机构并加锁，保持包装/仓库同机构及替代单同机构限制；详情补机构名称；运输由实际出库继承，不可改主体 |
| IoT 与设备绑定 | 设备归属分配及新增绑定校验机构；展示已分配设备机构；明确报文 `farmId` 与系统机构 ID 不是同一概念，不自动猜测归属 |
| 质检、退回、证据及 NFC | 保留来源机构权限和摘要/历史边界；直接关联全部纳入删除保护，不通过改机构重解释旧证据 |
| 日常助手与公众查询 | 助手继续按账号范围和业务来源查询，未开放机构管理工具；公众既有公开查询规则保留，不公开机构内部管理接口或联系方式 |
| 导航与权限 | 机构管理仅管理员可见，路由和后端服务双重限制；普通账号的机构名称接口仅返回本机构 |

选项接口仍为 `/api/production/organizations`；默认只返回启用机构，`includeInactive=true` 用于历史名称目录，仍受账号机构范围限制。前端统一目录将可选项与历史名称分开，避免停用后只显示数字编号。

## 部署与验证

无需数据库迁移或合约部署，使用已有 `sys_organization`、账号角色和审计表；更新前后端后生效。不会自动创建测试机构或修改经营记录。

- 后端 564 项回归、前端 40 项状态测试和正式构建通过。
- 独立临时 MySQL 库以真实 MyBatis 和事务检查机构增改/搜索、关联删除阻止、停启用、账号登录资格、选项与历史名称、跨机构拒绝、空机构删除及编码占用；临时库检查后清理。
- 真实浏览器只读登录现有环境，检查机构页 1440/1024/390/360 宽度、当前机构保护，以及产品/人员/地块/仓库/订单五处选择与刷新入口；检查不保存业务。
- 桌面、手机新建机构及手机产品表单截图已复核。硬件、MQTT 采样和链交易不在本轮新增测试范围；没有用这一轮机构检查替代全链路验收。

后续新增直接持有 `organization_id` 的业务表时，需同步补充机构删除依赖查询；不得只增加下拉选项而遗漏服务端有效性与范围校验。
