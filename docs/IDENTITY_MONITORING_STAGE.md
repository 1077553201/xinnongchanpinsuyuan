# 身份权限与监测归属：第二批实施记录

日期：2026-10-21

依据：[总体规划](PRODUCTION_TO_SALES_AGENT_PLAN.md)、[第一批实施记录](PRODUCTION_FOUNDATION_STAGE.md)。

## 1. 本批交付

在保留晨光绿、柔光玻璃两种外观的基础上，加入真实登录、角色权限、机构范围、固定设备绑定历史，以及按采集时间确定的种植环境归属。未实施采收销售、农事任务或 Agent 对话执行。

后台入口从无需登录调整为会话登录；公众扫码查询仍无需登录。新增“监测与设备绑定”和“账号与权限”页面，登录失效会返回登录页并保留可用的返回入口。

本批页面联调需连接真实后端；旧 mock 预览服务尚未模拟身份授权流程，不能通过 mock 账号或开发入口绕过登录。

## 2. 身份和权限

| 角色 | 本批业务权限 | 系统管理和旧模块 |
| --- | --- | --- |
| 管理员 ADMIN | 可维护全部机构的地块、种植与监测绑定 | 创建/停用账号、确认设备所属机构，可访问旧模块 |
| 生产人员 MANAGER | 仅维护所属机构的生产与监测记录 | 不能访问旧全局设备、批次、标签、交易等接口 |
| 只读人员 VIEWER | 仅查询所属机构地块、种植和监测 | 不可修改业务，不可访问人员列表 |

所有角色都可修改本人密码和退出登录。产品查询按机构范围过滤，产品创建检查所属机构。当前产品维护页面仍属管理员模块；生产人员在种植表单中选择管理员已配置的产品。

新生产服务同时校验权限与机构，不能只依靠隐藏按钮。尚未完成机构隔离的旧模块暂限管理员，不能声称所有旧业务已支持多机构人员协同。

登录采用服务端会话，浏览器不保存密码或访问令牌到 localStorage。Cookie 为 HttpOnly、SameSite=Strict，写请求要求会话 CSRF 校验；登录更换会话，空闲超时为 30 分钟。账号停用、机构停用、角色失效或密码修改后，后续请求会重新校验并拒绝旧会话。

密码使用随机盐和 PBKDF2-HMAC-SHA256，工作因子为 600,000。依据 [OWASP 密码存储指引](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。登录失败按实际连接地址限流；当前限流及会话均为单实例内存实现，不代表已完成公网或集群部署。

## 3. 首次登录和数据库升级

已有环境先执行 `database/migrations/002_identity_monitoring.sql`，新增五张表并补齐三类角色；前提是第一批生产表已经建立。新环境的 `database/schema.sql` 已包含本批结构和角色。

在仓库根目录完成后端编译后，也可以运行：

```powershell
& '<Java 11目录>/bin/java.exe' '-Dfile.encoding=UTF-8' `
  -cp 'backend/target/classes;<mysql-connector-java.jar路径>' `
  scripts/ApplyIdentityMonitoringSchema.java --bootstrap
```

脚本读取本地 `.env`，只执行本批建表与角色初始化。当 `sys_user` 尚无账号时，以首个有效机构创建 `local-admin`，随机密码仅保存到忽略文件 `.local/initial-admin.json`，不打印凭据。已有账号或凭据文件时不覆盖。已有旧账号的环境需先人工核对密码格式和角色，不能依赖脚本重置。

本机已完成增量建表和首次管理员初始化。请从本地凭据文件取登录资料，登录后通过“账号与权限”修改密码；文件保存的是初始密码，修改后不会自动更新它。

本地 HTTP 开发使用 `SESSION_COOKIE_SECURE=false`；启用 HTTPS 部署时设置为 `true`。正式运行还需单独完成 HTTPS、持久会话、备份、服务端密钥配置和部署验收。

## 4. 设备所属机构与绑定历史

设备所属机构通过 `device_ownership` 单独确认，不将旧 `farm_id` 猜作机构编号。旧设备和 MQTT 自动发现的设备初始不推断所属机构，须由管理员确认，之后才能绑定同机构地块的种植周期。

本批不支持设备跨机构转移。固定设备同一时刻仅允许一个活动绑定，绑定包含地块、种植周期、网关/农场上下文快照、起止时间及操作人。绑定立即生效，解除也按服务器当前时间生效，不允许用户回填历史时间。

绑定区间采用 `[started_at, ended_at)`：起点属于本轮，终点不属于旧绑定。迟到样本查询采集时刻的历史区间，不能按设备当前绑定倒推。缺少采集时间、未来时间、解绑空档、上下文不符或历史歧义时，保存原始读数和待核实原因，不进入正式汇总。

固定设备必须先解除旧绑定才能换地或换季。种植周期有活动绑定时不能结束；结束日期也不能早于该轮最后监测结束日期。小车跨地巡检需要独立任务与位置依据，本批明确拒绝将标识为小车/机器人车辆的设备当作固定传感器绑定。

## 5. 原始数据、环境窗口与测试数据

新增 `reading_provenance` 保存新样本的来源归属，新增 `window_provenance` 保存对应汇总窗口的种植、地块和绑定身份。既有原始表、链上记录和历史摘要不补造归属、不重新计算。

自动汇总按设备、指标、批次、种植周期、绑定与网关/农场上下文隔离；摘要包含新周期的来源身份。同一设备在同一时间桶中换地时分别汇总，手动聚合遇到混合来源拒绝执行。新种植周期尚无采收批次映射，因此不会采信设备报文自行指定的旧批次关系。

从本批开始，管理员“模拟采样”写入 `SIMULATED` 状态，不触发正式告警、正式窗口或上链，也不更新真实设备在线状态。模拟前要求已登记设备与网关。新设备报文为 `RAW`，只有匹配历史绑定的新样本进入正式环境统计；缺失来源的新报文保留待核实。旧数据的原始分类保持不变，不能据此断言旧 `RAW` 样本都来自真实硬件。

MQTT 主题与报文中的农场/网关字段必须一致。设备最近在线时间使用接收时间，迟到采样不会将其拨回过去。设备签名验真仍未实现，匹配绑定只表示记录归属明确，不等同于硬件身份或测量真实性已经核验。

本轮页面显示最近 100 条正式采集、最近 50 个窗口及绑定历史。未关联采收批次的窗口仅保存链下摘要，明确显示尚未存证；没有把旧合约中的产品批次伪装成种植周期上链。

## 6. 审计与并发

新增 `operation_audit`，记录账号创建/停用/改密、地块登记、种植开始/结束、设备所属确认、绑定/解绑的实际操作账号及业务对象。负责人姓名仍是业务填写字段，操作人身份由登录会话和审计单独记录。旧业务接口的完整审计扩展尚未完成。

生产状态变更使用 READ_COMMITTED 事务与地块行锁，绑定与采集按设备串行处理；活动设备唯一约束进一步阻止重复绑定。锁后读取当前周期状态，避免旧快照绕过结束条件。手动聚合也锁定设备，避免与自动采集并发产生过时的窗口版本。

## 7. 验证结果

- 后端 58 项测试通过，覆盖会话、密码存储、只读限制、CSRF、机构边界、来源歧义、缺失时间、模拟隔离、周期结束和跨周期汇总；前端现有 27 项测试、类型检查及生产构建通过。
- 真实 API 验证匿名拦截、公众查询保留、跨机构列表及对象访问限制、角色限制、密码变更失效、停用账号失效和退出登录。
- 通过本机 EMQX 实际发布非保留 MQTT 联调消息，验证换地前后、迟到样本、解绑空档、上下文不符与缺失采集时间；不同种植周期的样本数和窗口范围分别正确。
- 模拟 HTTP 样本不会进入正式采集、告警或窗口，独立核对了正式样本数没有增加。
- 浏览器完成实际登录、返回指定种植周期、解绑重绑、创建及停用只读账号、修改本人密码、只读按钮限制和会话失效跳转；桌面与手机布局检查通过。
- 真实接口连续三轮并发提交绑定与结束操作，每轮仅一个成功，结束周期没有残留活动绑定；验证后关闭了这组独立并发测试周期。
- 实际 MQTT 通道联调属于软件接入验证；发布端仍是测试程序，不是田间硬件验收。

测试使用 `QA-ID-*`、`QA-UI-*`、`QA-UIVIEW-*`、`QA-RACE-*` 等明确标记的独立记录。机构 B、测试账号、地块与设备不代表真实经营资料。结果和截图位于忽略目录 `.workbuddy/preview/identity-monitoring/`，测试凭据只保存在 `.local/`。

## 8. 下一批方向与保留边界

优先增加种植环境规则、农事任务与实际执行记录，再接采收、包装和库存销售。Agent 操作应复用现有服务权限、审计与状态校验，之后补上确认版本、幂等执行和失败恢复，不能直接写数据库。

待核实数据的人工审核、设备签名、传输去重与离线补传、小车巡检任务、机构与人员完整维护、密码找回、多实例会话，以及新周期到公众溯源和链上证据的完整关联，仍需后续实施。
