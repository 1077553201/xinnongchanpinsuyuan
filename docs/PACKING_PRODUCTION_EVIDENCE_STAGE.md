# 包装生产证据存证：批次 B 第一批实施记录

日期：2026-10-25。承接 [包装来源与赋码](PACKING_TRACE_CODES_STAGE.md)，对应 [下一阶段计划](NEXT_OPTIMIZATION_PLAN.md) NEXT-03/04 的生产证据部分。

## 入口与本批范围

进入“采收与包装 → 采收详情 → 查看来源与包装赋码”，点击“预览生产证据 / 刷新存证回执”。

1. 预览原包装来源、种植至采收的时间范围，以及将纳入的环境规则、实际农事执行和环境窗口。
2. 核对证据摘要与本页码范围，勾选确认，再提交当前页最多 20 个码。首次确认冻结证据版本 1；预览期间资料变化时拒绝旧确认，需重新读取。
3. 先登记包装批次摘要，再逐项绑定所选单品码。页面约每 1.5 秒读取回执；批次或前序项未成功时，后续保持未提交，可核对后恢复。
4. 公众扫码页显示这版生产证据、记录明细、冻结时间和摘要，并实时读链检查。未提交的同批其他码不会因批次已存证就自动显示通过。

本批复用既有 `registerBatch`、`bindItem` 和链上读取接口，不改变 Solidity、ABI、字节码或 Java wrapper；没有把原始传感器连续数据写上链。二维码身份、打印和一件一码规则继续复用上批实现。

## 证据选择与隐私边界

- 时间范围取自首次赋码时保存的原种植日期与原采收时间，采用北京时间。不能使用当前换季周期或查询时刻替代。
- 环境规则选取与该范围相交的版本，最多 200 条；农事仅选原周期中实际执行时间落在范围内的记录，最多 200 条，计划、取消和未执行事项不作为完成事实。
- 环境窗口必须属于原周期，起点不早于种植日、终点不晚于采收时点；跨越采收边界的窗口不纳入。同一绑定、设备、指标和时间范围有多个窗口版本时仅纳入最新版本，最多 50 条。
- 每类保留上限与截断标记，不把本版结果称为完整历史。无记录、缺测或单条数值在范围内均不等于整季环境或实物质量合格。
- 公众仅展示必要字段：农事类型、执行时间、投入品与数量；规则指标、范围、单位及有效期；环境统计值、时间、样本数与摘要。不公开人员、联系方式、私有说明、作业指令、凭证引用或设备访问凭据。
- 冻结后补录资料不会静默进入版本 1，不能覆盖已存证内容。冻结时间是链下登记时间，不能当作实地采集真实性或独立检测的证明。

## 摘要关联和状态

`原来源快照摘要 → 生产证据清单摘要 → 批次 payload.metadata → 链上批次摘要`，每个所选单品再通过链上绑定关联该批次。批次 payload 保存产品编码快照，避免后续修改产品主档导致历史证据被悄悄替换。

公众读取时检查来源快照、证据文本摘要、批次 metadata 和冻结内容一致性，再比较实时链上摘要、产品标识及单品所属批次。单纯数据库保存了 `CONFIRMED` 不足以让生产证据显示“链上摘要一致”。旧通用事件入口不用于替代真实农事或销售业务。

| 状态 | 含义及处理 |
| --- | --- |
| `NOT_SUBMITTED` | 未发送；读链暂不可用且尚未尝试写入时也保持未提交，并记录原因 |
| `PENDING` | 提交意图及交易记录已保存，等待结果 |
| `CONFIRMED` | 实时链上内容与预期一致；公众每次查询仍重新核验，不直接复用历史结论 |
| `FAILED` | 有明确失败回执，或已发现来源/摘要冲突；冲突不覆盖链上记录，需核对原因 |
| `CHAIN_DISABLED` | 本次链写入条件未启用，不能当作成功 |
| `UNCERTAIN` | 请求中断、结果未知或需进一步核对；单品/批次通用状态保留 `PENDING`，私有回执明确提示待核对 |

对未知结果先读链，查到匹配内容即可恢复；没有查到不代表原交易未发送，不能据此盲目重发。已知失败回执或禁用状态可在明确恢复操作中重试。尚无交易回执查询及人工裁决界面，长期未知且链上无记录的情形仍需后续完善对账流程。

## 事务和并发

新增 `packing_evidence` 保存不可变清单、批次 payload 和处理租约；`packing_evidence_job` 保存每个批次/单品的唯一处理任务、固定 payload、摘要、交易引用与结果。

先在独立数据库事务中锁定包装、确认版本和码归属、保存清单与任务，再执行外部链调用。发出每笔交易前另行持久化意图和交易记录，链调用不占用原数据库事务。回执持久化后再次读链核对，避免把远端成功与数据库回滚混成一次可重做的业务。

同包装使用五分钟租约串行处理；处理标识失效的旧请求不能覆盖新处理。每次提交的用户、证据摘要、所选码范围及逐项结果写入操作审计，不以共享链账户代替实际确认人。跨机构、只读、码不属于包装、重复选择或证据版本过期都在链写入之前拒绝。重试和恢复先检查已有链记录，已确认项不重复发送。
