## 2. 已具备的基础，后续应复用

1. Vue 管理端、晨光绿与柔光玻璃主题、全宽布局、移动端右侧主导航，以及真实登录、三类角色和新生产模块的机构范围控制。
2. 地块、种植周期、固定设备绑定历史；按采集时间保留监测归属；环境规则版本、异常处置、农事计划和实际执行。
3. 分次采收、分级及损耗核对、单一来源包装；仓库、分仓入出库与损耗、按仓库查看现货。
4. 多明细销售订单、分次销售出库、停止未出库余量；关联实际出库的运输安排、发运、进展、异常和后台收货记录。
5. 既有通用批次、单品码、二维码、NFC 绑定与公众查询、链上摘要核验能力。
6. AI 日常对话、私有历史、授权只读查询、实时执行轨迹与结果明细；操作单版本、逐项确认、回执与重试。实际写入工具目前只有采收和运输事件。

以上属于不同层次的基础能力，尚未共同构成“新种植业务到消费者扫码”的完整证据闭环。

## 4. 本次调研确认的主要缺口

| 核对位置 | 当前证据 | 对下一步的影响 |

## 7. 批次 A 的具体操作清单（软件基础已实施，保留验收依据）

1. 核对现有种植、采收、分级、包装、旧批次和单品码关系，确定查询身份、来源关联及唯一约束；对未明确的实物码单位提出具体问题。
2. 明确部分赋码、重复请求、不同规格、部分销售、包装未入库、已结束种植周期等场景；来源关系不因换季、设备解绑或后续销售改变。
3. 设计增量迁移，区分新业务与旧记录；不删除旧码、不重置业务、不凭空补齐历史来源。优先复用既有合约接口，需改合约时同步 ABI、字节码、Java wrapper 及集成说明。
4. 实现来源查询与赋码服务、前端操作入口和回执；用户确认后才产生码记录，数量校验与权限由后端执行。赋码与上链状态分别展示。
5. 用独立 QA 记录验证完整和部分赋码、并发防超量、请求去重、跨机构拒绝、换季后追溯，以及迁移兼容；向批次 B 提供稳定接口与样例。

## 8. 统一验收与记录规则

- 软件测试、真实 API/链联调、浏览器交互、截图视觉验收及实地验收分别记录；上一层通过不能替代下一层。
- 原规划的完整试点至少覆盖：同地块分次采收、不同包装去向、环境异常及处置、设备转移、种植换季、库存出库与交付，以及一段真实现场记录的 Agent 确认执行；启用退货时另验来源与数量回溯。
- 每批保存实现范围、迁移要求、验证结果、未完成事项及本地提交号；完成后执行适当检查并提交本地仓库，仅在用户要求时推送。
- 业务明细和原始采样链下保存，摘要与真实链状态分别展示；不把链上记录一致性解释为实物质量、设备身份或现场操作真实性的保证。
- 不在规划、日志样例、测试报告或仓库中保存密码、模型密钥、设备凭据和私钥。
